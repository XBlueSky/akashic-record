## Design Context

### Users
Platform developers exploring C/C++ codebases through a knowledge graph. They are backend/systems engineers who value precision, density, and code-level detail. They use this tool to onboard to unfamiliar repos, understand module dependencies, review AI-generated knowledge notes, and trace function call chains. Context is always technical — they read monospace, think in graphs, and want information density over whitespace.

### Brand Personality
**Mystical, Vast, Intelligent**

Akashic Record is a living knowledge palace — not a static documentation site. It should feel like entering a vast, dark chamber where constellations of code knowledge float in space, connected by luminous threads. The name itself references the "Akashic Records" — a cosmic compendium of all knowledge. The UI should honor that metaphor.

### Emotional Design (Two Modes)
- **Exploration mode** (Landing page, Graph view): Awe + curiosity. "I'm exploring a living knowledge palace." The 3D particle field, constellation graph, and glowing nodes should evoke the feeling of discovering something vast and interconnected.
- **Work mode** (Notes, Sidebar, Module detail): Control + efficiency. "I can find what I need instantly." Dense typography, compact layout, precise information hierarchy. Like a well-organized terminal or IDE panel.

### Aesthetic Direction
- **Theme**: Dark mode only. Deep navy backgrounds (`hsl(220 30% 4%)`), never pure black.
- **Primary accent**: Blue `#3B82F6` — used for focus, links, active states, and the central glow.
- **Glass morphism**: Used sparingly for overlays and panels (blur 32px, 45% card opacity). NOT on every element.
- **Glow effects**: Subtle blue glow on important interactive elements. Node glow in graph. Never gratuitous.
- **Typography**: Inter for UI, JetBrains Mono for code/technical content. Monospace is a first-class citizen, not a fallback.
- **Inspiration**: Neo4j Bloom's graph exploration feel + Obsidian's knowledge connectivity. But with its own identity — more cosmic, less utilitarian.
- **Anti-references**: Generic SaaS dashboards with white backgrounds. Notion-style minimalism (too flat for our metaphor). Overly playful/colorful designs (Figma, Linear — too casual).

### Design Principles

1. **Information density over decorative whitespace.** Every pixel should earn its place. Notes are compact. Sidebars are dense. The graph is the hero, not padding.

2. **Monospace is a design choice, not a fallback.** Technical content (code symbols, file paths, tags, metadata) uses JetBrains Mono. This signals "this is precise, machine-readable data" and aligns with the developer audience.

3. **Glow means importance.** Blue glow = primary interactive element or focus. Amber glow = human knowledge (notes). Don't put glow on everything — it loses meaning.

4. **Glass is for layered depth, not decoration.** Use glass morphism to create spatial hierarchy (sidebar over graph, modal over page). Don't use it on inline elements like badges or buttons.

5. **The graph IS the interface.** The constellation graph is not a feature — it's the core experience. Everything else (sidebar, notes, modules list) serves the graph. When in doubt, make the graph bigger.

### Color System

| Token | Value | Usage |
|-------|-------|-------|
| `--color-primary` | `#3B82F6` | Active states, focus rings, links, central glow |
| `--color-background` | `hsl(220 30% 4%)` | Page background (deep navy) |
| `--color-card` | `hsl(220 25% 7%)` | Card/panel backgrounds |
| `--color-border` | `hsl(220 15% 10%)` | Borders (very subtle) |
| `--color-muted-foreground` | `hsl(215 13% 45%)` | Secondary text |
| Category: ARCHITECTURE | `blue-400/500` | Blue badge/glow |
| Category: BUG_FIX | `red-400/500` | Red badge |
| Category: CONFIG | `amber-400/500` | Amber badge |
| Category: ONBOARDING | `green-400/500` | Green badge |
| Category: DECISION | `purple-400/500` | Purple badge |

### Typography Scale

| Size | Usage |
|------|-------|
| `text-[10px]` | Micro labels (legend, timestamps) |
| `text-[11px]` | Small labels (badges, file paths) |
| `text-[12px]` | Metadata (facts, secondary info) |
| `text-[13px]` | Default component text (notes, sidebar) |
| `text-sm` (14px) | UI text (buttons, inputs) |
| `text-lg`+ | Only for landing page title |
